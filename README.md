# Iron Cell Arena V2

## V6.21 직접 발동·선택 취소·실물 무기 연출

- 집합체 Q/R/T/Y 버튼은 포인터를 떼는 과정 없이 누르는 순간 직접 발동하도록 변경했습니다.
- 스킬 선택창에 ‘이번 선택 취소’를 추가했으며 대기 창이 여러 개면 현재 한 장만 사라집니다.
- 천뢰 창은 원근감 있는 하늘 지점에서 실제 번개 창이 낙하하고 지면 그림자와 충격파가 생깁니다.
- 세계 절단은 실물 대검이 나타나 회전하며 베고 검 궤적을 남깁니다.

## V6.20 집합체 전투 규칙형 스킬 개편

- 범위 공격과 다발 탄환 중심 구성을 줄이고 적 탄환 반사, 위치 저장·귀환, 탄환 소거, 단일 대상 구속·처형, 은신, 쿨다운 거래, 4초 시간 역행, 부활, 공간 도약으로 교체했습니다.
- 귀환 닻은 첫 사용으로 위치와 체력을 저장하고 두 번째 사용으로 돌아가는 2단계 스킬입니다.
- 과부하 거래는 체력을 소모해 장착한 다른 세 스킬의 대기시간을 즉시 초기화합니다.
- 관성 역전은 새 탄환을 만들지 않고 실제 적 탄환의 소유권과 진행 방향을 반전합니다.

## V6.19 집합체 스킬 개성·등급 강화

- 집합체 Y 스킬이 기존 데쿠 전용 보호 로직에 의해 취소되던 문제를 수정하고 키 입력 즉시 발동을 추가했습니다.
- 일반 1.0배, 희귀 1.7배, 영웅 2.8배, 전설 4.5배, 신화 7.0배로 등급별 전투력을 명확히 구분했습니다.
- 15개 스킬을 산탄, 순간 이동, 회복 방어, 흡인, 방사형 빙결탄, 궤도 포탑, 관통 번개, 분신 사격, 유성, 시간 연쇄 폭발, 부활, 맵 절단, 우주 폭풍, 절대 보호막 등으로 재구성했습니다.
- 각 스킬의 조준 미리보기도 부채꼴·직선·돌진·지정 범위·자기 강화로 구분했습니다.

## V6.18 집합체 무한 적응 성장

- 집합체 탱크는 레벨 제한과 진화가 없고, 레벨당 필요 경험치가 완만하게 증가합니다.
- 처음에는 스킬이 없으며 3레벨마다 전투를 멈추지 않는 작은 선택창에서 새 스킬을 고릅니다.
- 일반·희귀·영웅·전설·신화 등급마다 3개씩, 총 15개의 서로 다른 전투 스킬을 추가했습니다.
- 스킬은 최대 4개까지 Q/R/T/Y에 장착되며, 이후 선택에서는 원하는 칸을 즉시 교체합니다.

## V6.17 머신건 동시 분산 사격

- 머신건 진화체는 일반 사격이 좌우로 미세하게 분산되고, 세 번째 발사 주기에는 5발이 한 프레임에 부채꼴로 발사됩니다.
- 머신건 진화체에 넓은 리시버, 냉각 홈, 확장 총구가 있는 전용 대포 외형을 적용했습니다.

## V6.16 싱귤러리티 지급·장착 V3

- 캐시된 구버전 함수를 사용하지 않도록 관리자 지급과 장착 RPC를 새 V3 이름으로 분리했습니다.
- 관리자 지급과 일반 장착 모두 서버 저장 결과를 반환하고 클라이언트가 결과를 검증합니다.

## V6.15 검증형 장착 RPC

- 새 장착 RPC V2를 사용해 이전 함수 캐시와 권한 문제를 피합니다.
- 서버가 반환한 장착 대포가 요청한 대포와 일치할 때만 장착 완료로 처리합니다.

## V6.14 싱귤러리티 장착 권한 수정

- 보유한 집합체와 고죠를 장착할 때 로그인 사용자 본인의 프로필만 서버 권한으로 갱신합니다.
- 장착 실패 시 실제 서버 오류를 화면에 표시해 원인을 확인할 수 있습니다.

## V6.13 싱귤러리티 하단 표시 보강

- 고죠와 집합체를 원래 등급 순서대로 보관함 맨 아래에 표시합니다.
- 검증된 `bidulgy` 관리자 계정은 이전 프로필 캐시가 남아 있어도 보유한 두 싱귤러리티 탱크를 선택할 수 있습니다.

## V6.12 특이점 탱크 상단 고정

- 획득한 고죠와 집합체 탱크를 보관함 선택 목록 최상단에 표시합니다.
- 특이점 탱크 카드에 보유 특수 탱크 표시를 추가해 일반 대포와 쉽게 구분됩니다.

## V6.11 특이점 탱크 선택 동기화

- 보관함을 열 때 서버 프로필을 다시 불러와 관리자 지급 탱크가 즉시 선택지에 나타납니다.
- 서버가 보유권을 확인한 고죠와 집합체 탱크를 정상적으로 장착할 수 있습니다.
- `bidulgy` 계정의 고죠와 집합체 보유 상태를 운영 DB에서 복구했습니다.

## V6.10 관리자 융합체 지급

- 관리자 패널의 대포 지급 목록에 융합체 탱크를 추가했습니다.
- 관리자 검증 RPC에서 융합체 지급과 회수를 허용합니다.
- 일반 사용자는 직접 획득하거나 관리자가 지급하기 전까지 융합체 슬롯을 볼 수 없습니다.

## V6.09 진화 대포 유지·오토 5 추적 개선

- 2단·3단 진화체도 진화 전 장착 대포의 고유 외형을 모든 포신에 유지합니다.
- 오토 5의 다섯 포탑을 표적 유무와 관계없이 항상 표시합니다.
- 표적이 없을 때는 포탑이 마지막 방향에서 대기하고, 표적이 들어오면 천천히 회전한 뒤 조준이 맞은 포탑만 자동 발사합니다.
- 오토 5 포탑 방향을 네트워크로 동기화해 다른 플레이어에게도 같은 움직임이 보입니다.

## V6.08 전투 보석 보상

- 전투 EXP 1당 보석 5개를 지급하도록 서버 정산식을 변경했습니다.
- 사망 화면과 차고 안내도 같은 1:5 비율로 통일했습니다.


## V6.07 오토 5 자동 사냥·중앙 밀집 복구

- 오토 5의 다섯 포탑을 크게 표시하고 각 포탑이 가까운 적을 독립적으로 조준합니다.
- 사거리 안에 적이 있으면 입력 없이 자동 발사하며 탄환은 실제 포탑 위치에서 생성됩니다.
- 중앙 오각형을 기존의 200마리 밀집 배치로 복구했습니다.

## V6.06 집합체 보스

- 중앙 오각형을 200개에서 120개로 줄이고 더 넓은 나선 범위에 배치했습니다.
- 매시 정각과 30분에 월드 중앙에 체력 1,000,000의 집합체 보스가 생성됩니다.
- 처치 보상은 피해 기여도에 따라 소환석 최대 1,000,000개, 집합체 탱크 최대 10% 확률로 서버에서 1회 지급됩니다.
- 집합체 탱크는 획득한 계정의 보관함에만 나타나며 미획득 계정과 관리자 패널에서는 숨겨집니다.
- 전장 배경을 흰색과 옅은 청회색 격자로 교체했습니다.

## V6.05 조준 안정화와 스킬 문양 분리

- 카메라 갱신과 조준 계산 순서를 맞추고 이동 후 조준각을 다시 계산해 조종 중 포신이 미세하게 흔들리던 현상을 줄였습니다.
- 벽, 포격, 투사체, 돌진, 지뢰, 무기 강화처럼 자체 형상이 분명한 스킬에서는 공통 마법진을 제거했습니다.
- 시간은 시계판, 중력과 공허는 궤도와 소용돌이, 얼음은 육각 눈송이, 번개와 플라즈마는 다각 회로, 별 계열은 별자리 노드로 서로 다른 마법진을 사용합니다.

## V6.02 Supabase 무료 한도 보호

- AWS WebSocket의 110ms 상태 전송과 650ms 월드 동기화는 유지합니다.
- Supabase fallback은 플레이어 상태를 1.2초, 월드 스냅샷을 5초 간격으로 제한합니다.
- Supabase에서는 탄환 초기 속도로 위치를 보간하고 고빈도 `shotSync` 방송을 생략합니다.
- 진행 자동 저장 간격을 8초에서 30초로 늘려 DB 쓰기와 API 전송량을 줄입니다.
- `supabase_quota_diagnostics.sql`로 삭제 없이 DB/테이블/인덱스 용량을 확인할 수 있습니다.

- 아오와 아카의 회전 에너지 흐름, 무라사키의 색상 교차와 끝부분 폭발을 강화했습니다.

## V5.92 고죠 스킬 연출

- 아카는 E를 누르는 동안 대포 앞에 붉은 구슬이 맺히고, 놓으면 빠르게 날아가는 연출로 바뀝니다.
- 아오는 커서 위치의 큰 푸른 원에 회전하는 바람을 표시하며, 시전 후 주변 도형을 중심으로 끌어옵니다.
- 무라사키는 푸른색과 붉은색 에너지가 교차하는 독자적인 광선 연출을 사용합니다.

## V5.94 고죠 연출 재구성

- 고죠 스킬에서 공통 마법진을 제거하고 각각 다른 응축·발사·흡인 움직임으로 교체했습니다.
- 아오는 커서 위치의 푸른 핵으로 공기 흐름과 입자가 나선형으로 빨려 들어가며 적을 끌어옵니다.
- 아카는 대포 앞에서 붉은 에너지가 응축된 뒤 버튼을 놓는 순간 고속 구체로 발사됩니다.
- 무라사키는 고정 광선 대신 작은 보라색 핵이 전진하며 뒤쪽 공간과 색을 길게 끌고 가는 연출입니다.

## V5.95 고죠 조작·충돌 판정 재구성

- 아오는 Q를 누르는 동안만 활성화됩니다. 푸른 핵이 실시간으로 커서를 따라가며 범위 안의 적을 계속 끌어당기고 지속 피해를 줍니다.
- 아카는 응축된 붉은 탄체가 목표 지점에 도착한 뒤 폭발하며, 비행 중 목표 지점에 미리 피해나 밀치기가 적용되지 않습니다.
- 무라사키는 아오와 아카가 양쪽에서 휘어 들어와 합쳐지는 준비 동작 뒤 보라색 탄체가 전진합니다.
- 무라사키 피해는 발사 순간의 직선 전체에 즉시 적용되지 않고, 이동하는 탄체의 충돌 범위가 적에게 닿을 때만 적용됩니다.

## V5.96 고죠 지급 복구

- 관리자 패널은 검증 가능한 `iron_cell_admin_set_cannon_v2`를 우선 호출하고, 지급 후 서버 프로필을 다시 조회해 실제 저장 여부를 확인합니다.
- 고죠 장착 플레이어가 죽으면 정산 완료 후 피해를 준 플레이어와 실행 ID를 서버에 증명합니다.
- 처치자는 동일 실행 ID를 재확인하며, 양쪽 증명이 일치한 경우에만 고죠가 소유 대포에 추가됩니다.
- 피해자의 정산보다 처치 알림이 먼저 도착하는 경우를 위해 처치 확인을 제한적으로 재시도합니다.

## V6.01 20인 자동 아레나 분할

- 한 아레나의 최대 인원을 20명으로 제한합니다.
- 접속자는 인원이 있는 빈자리 방에 우선 배정되고, 방이 가득 차면 다음 독립 방이 자동 생성됩니다.
- 위치, 총알, 스킬, 피해, 오각형 월드 상태는 같은 방의 플레이어에게만 전송됩니다.
- 재접속한 동일 계정은 이전 연결을 정리한 뒤 다시 방을 배정받습니다.
- `/health`에서 현재 방 수, 전체 접속자 수, 방당 최대 인원을 확인할 수 있습니다.

## V6.00 AWS 실시간 서버 연결

- AWS WebSocket 서버가 설정되어 있으면 게임이 `/arena-ws`로 우선 연결합니다.
- Supabase 로그인 액세스 토큰을 AWS 서버에서 다시 검증하므로 임의 사용자 접속을 막습니다.
- AWS 연결 실패 시 기존 Supabase Realtime으로 자동 복귀해 전투 입장을 유지합니다.
- App Runner용 `apprunner.yaml`, 컨테이너용 `Dockerfile`, Node 실행용 `package.json`을 포함합니다.
- 배포 후 `arena-config.js`의 주소를 `wss://발급주소/arena-ws`로 설정하면 연결이 활성화됩니다.
- 상태 점검 주소는 `https://발급주소/health`입니다.

### AWS App Runner 환경 변수

- `SUPABASE_URL`: 게임이 사용하는 Supabase 프로젝트 URL
- `SUPABASE_PUBLISHABLE_KEY`: Supabase publishable key
- `MAX_ARENA_PLAYERS`: 기본값 20
- `MAX_ARENA_SHARDS`: 한 프로세스에서 만들 수 있는 최대 방 수, 기본값 100
